# 架构说明

> 本文档由团队共同维护。**接口冻结（W2）后，改动此文件需要全员同意。**

## 一次执行的完整链路

```
用户目标
   ↓
Planner        拆成子任务 + 依赖关系（DAG）
   ↓
Auctioneer     每个子任务广播，Agent 竞标，选一个
   ↓
Agent          中标者执行，产出 Artifact
   ↓
QualityGate    三层校验：格式 → 语义 → 影响
   ↓
通过 → 入库     不通过 → 重试（最多 3 次）→ 耗尽则重规划
   ↓
ConflictResolver  检测并消解跨 Agent 冲突
   ↓
最终结果（成果物 + 指标 + trace）
```

## 模块职责边界

| 模块 | 负责 | **不负责** |
|---|---|---|
| Planner | 目标→子任务 DAG、失败后重新分解 | 分配任务、执行、校验 |
| Auctioneer | 广播、收 Bid、评分、授标 | 任务分解、执行、失败处理 |
| Agent | 竞标、执行、上报结果 | 决定谁中标、校验质量 |
| Orchestrator | 主循环、状态机、并发、重试/重规划决策 | 各模块内部细节 |
| QualityGate | 格式/语义/影响三层校验、结构化反馈 | 修改成果物、决定重试 |
| ConflictResolver | 检测冲突、给出消解策略 | 判断单个成果物质量 |
| StateStore | 存取成果物与状态、支持回放 | 校验、判断、决策 |

## 状态机

```
PENDING → BIDDING → RUNNING → REVIEWING
                                   ├─ DONE
                                   ├─ PENDING（重试，retry_count < max）
                                   ├─ REPLANNED（重试耗尽，拆成子任务）
                                   └─ IMPOSSIBLE（无人能接）
```

> ⚠️ **已知陷阱**：任务变 `REPLANNED` 后，下游任务的 `depends_on` 还指着它，
> 而「就绪」判断要求依赖状态**恰好是 DONE** → 下游永远等不到 → 整条链卡死。
> **重规划后必须把下游依赖改接到新子任务的叶子节点。**
