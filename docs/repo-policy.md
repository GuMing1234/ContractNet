# 仓库公开守则

> ⚠️ **本仓库是 Public（全世界可见）。**
> 你提交的每一行代码、每一条提交信息、每一个邮箱，都会被永久记录。
> **推送出去就收不回来。**

---

## 一、这意味着什么（三句话）

1. 老师、同学、面试官、陌生人，都能看到
2. 爬虫会抓，搜索引擎会缓存，代码存档站（如 Software Heritage）会存档
3. **删文件、转私有，都不能彻底收回**

**所以：推之前想一秒。**

---

## 二、绝对不能提交的东西（黑名单）

| 类型 | 例子 | 为什么致命 |
|---|---|---|
| **密钥** | `.env`、`sk-xxx`、token、密码 | 泄露后别人能用你的额度，账单算你的 |
| **个人信息** | 学号、手机号、身份证、住址 | 公开 = 永久公开 |
| **参考实现** | `ContractNet-学长版/`、`reference/` | 涉及他人代码版权 + 学术诚信 |
| **大文件** | 视频、数据集、`.zip` | 仓库永久变大，所有人 clone 变慢 |
| **运行垃圾** | `__pycache__/`、`.idea/`、`out.txt` | 显得不专业 |
| **内部笔记** | 老师的要求、评审意见、你的吐槽 | 不该被外人看到 |

`.gitignore` 已经挡掉了大部分，但**它挡不住 `git add -f`（强制添加）**。

## 三、每个人的隐私设置（第一周必须做完）

**为什么**：commit 里的邮箱**永久公开**。QQ 邮箱常带手机号（比如 `xxx13703594591@qq.com`），等于把手机号挂在网上。

### 三步

**1.** GitHub → 右上角头像 → **Settings** → **Emails** → 勾上

> ☑️ Keep my email addresses private

会得到形如 `12345678+你的用户名@users.noreply.github.com` 的地址。

**2.** 本地设成这个地址

```powershell
git config --global user.email "12345678+你的用户名@users.noreply.github.com"
git config --global user.name "你的名字或昵称"
```

**3.** 验证

```powershell
git log -1 --format="%an <%ae>"
```

输出里应该是 `users.noreply.github.com`，不是你的真实邮箱。

## 四、提交前 60 秒自检

```bash
git status                                          # 有没有 .env、笔记、参考实现混进来
git diff --stat                                     # 改了哪些文件、多少行（超过 400 行考虑拆）
git ls-files | grep -iE "env|key|secret|token|参考|学长|reference"
```

**三条都过再 `git add`。**

多花 60 秒，能省掉一次「密钥泄露 + 全组换 key」。

## 五、提交信息怎么写（公开仓库特有）

### 为什么这件事在 public 仓库特别重要

> **你的 commit history 就是你的工作证据。面试官会翻。**

| 看到这样的 history | 面试官想 |
|---|---|
| `feat(planner): 用 LLM 替换写死的分解模板` | 这人真在做事 ✅ |
| `fix(auctioneer): 通配 Agent 不再无条件拿满分` | 这人会找 bug ✅ |
| 每天/每两天一次小提交 | 这是连续几个月的真实工作 ✅ |
| `update` / `fix` / `1` / `改了一些东西` | 敷衍 ⚠️ |
| 某天一次性提交 3800 行 | 这不是他写的 ❌ |

### 格式

```
类型(模块): 做了什么
```

| 类型 | 什么时候用 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 只改文档 |
| `refactor` | 重构，不改变行为 |
| `test` | 测试 |
| `chore` | 杂事（配置、依赖） |

**例子**

```bash
git commit -m "feat(planner): 用 LLM 替换写死的分解模板"
git commit -m "fix(quality_gate): 无裁判时 score 返回 None 而不是阈值"
git commit -m "docs(repo-policy): 加公开仓库守则"
```

### ⛔ 一条禁令

**不要在 commit message 里写「照搬学长」「copy from xxx」。**

参考了规范写法（比如 OpenAI 的 tool_calls 格式），那是协议，不是抄；
参考了**设计选择**，去 `docs/decisions/你的名字.md` 里写清楚。

> 诚实留痕 = 加分（证明你会读代码、会判断）
> 偷偷抄被发现在 commit message 里 = 致命

## 六、参考实现的边界

学长的仓库是公开的，我们的也是。**任何人（包括面试官）都能对比两份代码。**

| 规则 | 说明 |
|---|---|
| **只读，不复制** | 整段复制 = 违反铁律 6 |
| **不放进本仓库** | `.gitignore` 已加防御段，但不要手动 `git add -f` |
| **参考了要留痕** | 写进 `docs/decisions/你的名字.md` |
| **不要一次性提交大段代码** | 这比"抄"本身更容易被识别出来 |

## 七、万一泄露了怎么办（应急流程）

### ⭐ 记住顺序：**先吊销，再删除。反过来没用。**

因为历史已经公开了，删文件不会让已经被抓走的内容消失。

### 密钥泄露

1. **立刻去服务商后台吊销/重置那个 key** ← 这是唯一真正有效的一步
2. 查账单，看有没有异常调用
3. 删文件 → 提交 → 推送（减少后续暴露）
4. **在群里通知所有人**，让他们检查自己的 key
5. 把教训写进 `docs/decisions/`

> 如果只是刚提交还没 push：立刻 `git rm --cached .env` + `git commit --amend`，来得及。

### 个人信息泄露

1. 立刻改文件，删掉那部分
2. 如果只有最新一次提交：`git commit --amend` 后 `git push --force-with-lease`
3. 如果在历史深处：需要 `git filter-repo` 重写历史（对新手很难，叫负责人或学长一起做）
4. 涉及手机号/身份证：**考虑先把仓库转 Private**，处理完再公开

### 提交了别人的代码

1. 立刻改成自己的实现
2. 在 `docs/decisions/` 里补说明
3. **在群里说清楚，不要隐瞒** —— 隐瞒的代价远大于承认

## 八、权限说明

| 角色 | 能做什么 |
|---|---|
| **负责人** | 合并 PR、改仓库设置、管理分支保护、邀请成员 |
| **全体成员** | 建分支、提 PR、开 Issue、评论、Review |

**谁都不能直接 push `main`。**

这不是不信任谁，是因为 8 个人推同一个分支，两天就会互相覆盖一次，而且没人能查是谁改坏的。

## 九、常见事故对照表

| 现象 | 原因 | 怎么处理 |
|---|---|---|
| `push` 被拒绝 | `main` 受保护 | 正常。改推自己的分支，然后开 PR |
| `rejected - non-fast-forward` | 你的分支落后了 | `git merge main` 后再推 |
| PR 显示几十个文件改动 | 分支是从旧代码分出来的 | 关掉 PR，从最新 `main` 重新开分支 |
| 看到 `<<<<<<< HEAD` | 冲突了 | 打开文件，删掉标记行，留想要的代码 |
| 不小心提交了 `.env` | 用了 `git add -f` | 按第七节：**先吊销 key** |
| `clone` 特别慢 | 仓库里进了大文件 | 找负责人清理历史 |
| 改了 `core/types.py` 别人全崩 | 违反铁律 4 | 在群里说明，立刻修复 |
